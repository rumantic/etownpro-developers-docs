# Вопрос-ответ

## `POST /api/v1/chat/ask`

Задать вопрос по базе знаний аккаунта.

**Тело запроса** (`application/json`)

| Поле | Обязательно | Описание |
|---|---|---|
| `question` | да | текст вопроса, 2–2000 символов |
| `section` | нет | ограничить поиск одним разделом (см. [список разделов](03-documents.md#разделы-базы-знаний)) |
| `document_id` | нет | ограничить поиск одним конкретным документом (например, «чат с этой книгой») |

```bash
curl -X POST https://ваш-сайт.ru/api/v1/chat/ask \
  -H "Authorization: Bearer <ключ>" \
  -H "Content-Type: application/json" \
  -d '{"question": "Сколько стоит доставка по Москве?"}'
```

**Ответ `200`**

```json
{
  "data": {
    "answer": "Доставка по Москве — 500 ₽, бесплатно от 5000 ₽.",
    "sources": [
      { "document_id": "42", "file_name": "price-list.pdf", "section": "delivery", "chunk_index": 3 }
    ]
  }
}
```

`sources` — список фрагментов документов, на основе которых сформирован
ответ. Если в базе знаний не нашлось ничего релевантного вопросу,
`sources` будет пустым массивом, а `answer` — вежливой формулировкой
«не знаю» вместо выдуманного ответа. Проверяйте `sources.length`, если
вашей интеграции важно отличать «нашли ответ» от «ничего не нашли»,
не полагаясь только на текст `answer`.

## Важно

- **Без памяти диалога.** Каждый вызов независим — API не хранит и не
  учитывает предыдущие вопросы в рамках «беседы». Если нужен
  многошаговый диалог — собирайте контекст на своей стороне и
  передавайте его как часть `question`.
- **Иногда `502`.** Если сервис ответов на вопросы временно недоступен,
  вернётся `502 service_unavailable` — это транзиентная ошибка,
  повторите запрос через несколько секунд. См.
  [«Ошибки и лимиты»](05-errors-and-rate-limits.md).
