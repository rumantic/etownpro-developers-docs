# Skills — как устроена система и как с ней работать

Документ для тех, кто администрирует конфигурацию `skills` (наполняет базу
контентом) и хочет понимать, как система принимает решения — какую
профессию показать школьнику и какие задания ему назначить. Техническая
спецификация домена — [`plan/spec_test_system.md`](plan/spec_test_system.md);
здесь — практическое руководство «как это работает» и «что делать руками».

---

## 1. Общая идея одним абзацем

Школьник проходит тесты → система вычисляет его уровень по каждому навыку
→ сравнивает профиль навыков с требованиями профессий → показывает, какая
профессия подходит лучше всего (в процентах) → школьник выбирает цель →
система ежедневно подбирает задания на навыки, которых не хватает до этой
цели → школьник выполняет задания и время от времени пересдаёт тесты →
видит, как его % соответствия растёт → если его реальный профиль навыков
со временем оказывается ближе к другой профессии — система сама это
замечает и предлагает сменить цель.

```
Тест → Ответы → Уровень навыка → Соответствие профессии → Задания → Пересдача → Прогресс
```

## 2. Путь школьника (что видит пользователь)

| Шаг | Страница | Что происходит |
|---|---|---|
| 1. Анкета | `/skills/onboarding` | Возраст, школа — один раз, до первого теста |
| 2. Тестирование | `/skills/tests` → `/skills/tests/{id}` | Список тестов (по одному на навык), прохождение, мгновенный результат в % |
| 3. Мой профиль | `/account/skills` | Возраст/школа, **профиль навыков** (уровень по каждому навыку + дельта «было/стало»), текущая целевая профессия и график динамики, история всех попыток |
| 4. Профессии | `/skills/professions` | Топ профессий по % соответствия, кнопка «Выбрать целью», баннер с предложением сменить цель (если система его выставила) |
| 5. Задания | `/skills/tasks` | Задания на сегодня, подобранные под дефицит навыков текущей цели, отметка выполнения чекбоксом |

Школьник ничего не вводит вручную для расчётов — все числа (уровень
навыка, % соответствия, дефицит) считаются автоматически на основе
пройденных тестов.

---

## 3. Как считаются числа (без формул, на пальцах)

### 3.1 Уровень навыка

Уровень школьника по навыку = результат **последней** попытки теста этого
навыка (в процентах, 0–100). Если тест пересдавали несколько раз — считается
только последняя попытка, вся история хранится и видна на `/account/skills`.
Текстовая метка уровня:

| % | Метка |
|---|---|
| 0–24 | Начальный |
| 25–49 | Средний |
| 50–74 | Продвинутый |
| 75–100 | Экспертный |

### 3.2 Соответствие профессии (%)

Каждая профессия описана набором требований: «нужен навык X на уровне не
ниже Y, вес важности W». Соответствие считается так:

- по каждому требуемому навыку берётся **меньшее** из (текущий уровень
  школьника, требуемый уровень) — то есть избыток по одному навыку не
  компенсирует нехватку по другому;
- результат взвешивается по важности навыка (`weight`) и переводится в
  проценты от максимально возможного значения.

Отдельно считается **«оценено: N%»** — доля требований, по которым
школьник вообще проходил тест хоть раз. Это специально показывается
отдельно от самого %, чтобы не путать «слабый навык» с «навык ещё не
проверялся» — 0% без единой попытки не должно выглядеть как «ты плохой».

### 3.3 Ежедневные задания

Каждый день (при первом заходе на `/skills/tasks`) система:
1. Смотрит на выбранную цель школьника;
2. Считает дефицит по каждому требуемому навыку профессии (насколько
   текущий уровень ниже требуемого, с учётом важности навыка);
3. Берёт **3 навыка** с наибольшим дефицитом (число настраивается,
   см. раздел 5);
4. Под каждый навык подбирает одно задание из банка — на уровень сложности,
   соответствующий текущему уровню школьника по этому навыку, стараясь не
   повторять задание, которое уже давали за последние 7 дней.

Если у школьника ещё нет выбранной цели — заданий не будет, страница
подскажет сначала выбрать профессию. Если по всем требованиям профессии
уже всё в порядке — система добирает задания на объективно самые слабые
навыки школьника вообще, чтобы день не был пустым.

**Важно:** выполнение задания само по себе НЕ повышает уровень навыка —
это только практика. Реальный прогресс (и новый %) появляется только
после **пересдачи теста**.

### 3.4 Когда система предлагает сменить профессию

После каждой пересдачи любого теста система пересчитывает % соответствия
по всем профессиям и, если другая профессия обгоняет текущую цель школьника
хотя бы на **10 процентных пунктов**, и это подтверждается **2 попытки
подряд** (не разовый всплеск) — на `/skills/professions` появляется баннер
с предложением сменить цель. Школьник может принять (цель меняется) или
отклонить (баннер пропадает, цель остаётся прежней, предложение может
появиться снова после следующей пересдачи).

## 4. Путь администратора — что и где

Все админ-страницы — под `/admin/skills/*`, доступны роли admin.

| Раздел | URL | Что настраивается |
|---|---|---|
| Навыки | `/admin/skills/skills` | Список навыков (название, slug, цвет, описание) |
| Тесты | `/admin/skills/tests` | Тесты (по одному на навык), вопросы, варианты ответов с баллами |
| **Профессии** | `/admin/skills/professions` | Профессии + их требования к навыкам (это и есть «профессиограмма») |
| **Банк заданий** | `/admin/skills/development-tasks` | Шаблоны заданий на развитие навыков |
| Dashboard | `/admin` | Общая статистика: тестов, навыков, попыток, профессий, учеников |

### 4.1 Как добавить новый навык

`/admin/skills/skills` → «Новый навык»: slug (латиницей, для внутренних
ссылок), название, цвет (для UI), описание. Навык сам по себе ни на что не
влияет, пока к нему не привязан тест и требования профессий.

### 4.2 Как добавить тест на навык

`/admin/skills/tests` → «Создать тест»: выбрать навык, название,
длительность в минутах, затем добавить вопросы. У каждого вопроса — минимум
2 варианта ответа, у каждого варианта — **баллы от 0 до 3** (3 — самый
правильный/развитый ответ). Итоговый % = сумма набранных баллов / сумма
максимально возможных баллов по всем вопросам. Баллы вариантов не видны
школьнику ни на одном экране (намеренно, чтобы нельзя было вычислить
правильный ответ по интерфейсу).

### 4.3 Как добавить профессию (самое важное для подбора)

`/admin/skills/professions` → «Создать профессию»: slug, название, цвет,
описание, затем — **требования к навыкам**:

- **Навык** — из уже существующих;
- **Требуемый уровень (0–100)** — насколько хорошо школьник должен владеть
  этим навыком для этой профессии. Ориентир: 30 — навык желателен, но
  некритичен; 55–65 — навык нужен на среднем уровне; 80+ — навык критичен;
- **Вес (0.1–5)** — насколько этот навык важнее других требований этой же
  профессии. 1.0 — обычная важность, 1.5 — заметно важнее, 0.5 — менее
  важен, чем остальные. Веса **не** обязаны суммироваться до конкретного
  числа — они сравниваются только внутри одной профессии.

Практический совет: у профессии должно быть требование **по каждому**
существующему навыку (даже с низким `required_level`, например 20–30) —
иначе «оценено: N%» будет заведомо ниже 100%, даже если школьник прошёл
все тесты, просто потому что для непокрытых навыков нет требования вообще.

Пример из сидированных демо-данных («Аналитик»): аналитическое мышление
85/вес 1.5, логика 80/1.4, внимательность 70/1.1, коммуникация 55/0.8,
креативность 30/0.5.

Профессию можно сделать неактивной («Активна» = выключено) — она перестанет
участвовать в подборе и не будет видна школьникам, но история снапшотов и
уже выбранных целей не удаляется.

### 4.4 Как добавить задание в банк развития

`/admin/skills/development-tasks` → форма (навык, название, описание,
длительность в минутах, уровень сложности, активность):

- **Уровень сложности** — `beginner` (для школьников с уровнем навыка
  0–39%), `intermediate` (40–74%), `advanced` (75–100%). Система подбирает
  задание именно под текущий уровень школьника по этому навыку — не давайте
  «продвинутое» задание единственным вариантом на навык, иначе новичкам
  будет назначаться оно же (когда нет альтернативы, ограничение по уровню
  снимается, лучше дать хоть какое-то задание, чем ни одного).

Рекомендуется минимум 2–3 шаблона на пару (навык × уровень), чтобы система
могла чередовать задания и не повторять одно и то же каждый день (см. 3.3
про cooldown в 7 дней).

### 4.5 Массовое наполнение через сидеры (для разработчика/оператора)

Если нужно быстро наполнить **нового** тенанта демоданными (например, для
демонстрации), на сервере доступны (через `php artisan db:seed --class=...`):

- `App\Configs\Skills\Database\Seeders\SkillsSeeder` — 5 базовых навыков + 5
  тестов с вопросами;
- `App\Configs\Skills\Database\Seeders\ProfessionsSeeder` — 5 демо-профессий
  с требованиями (зависит от SkillsSeeder — требования ссылаются на навыки
  по slug);
- `App\Configs\Skills\Database\Seeders\DevelopmentTaskTemplatesSeeder` — 15
  шаблонов заданий (5 навыков × 3 уровня сложности).

Все три идемпотентны (`updateOrCreate`) — безопасно перезапускать. Они
проходят **по всем** тенантам с `app_type = skills` сразу — если тенантов
с этим типом несколько, а нужно засеять только один конкретный, точечный
способ (без правки кода сидеров) — привязать `currentTenant` к нужному
тенанту и вызвать приватный метод `seedForTenant()` сидера через reflection
в `artisan tinker`. Так это было сделано при первом наполнении прод-тенанта
`16140ai.etownpro.ru`.

## 5. Настраиваемые константы

Файл `configs/skills/api/config/skills.php` (доступ — `config('skills.*')`,
используется сервисами `ProfessionSuggestionEngine` и
`DevelopmentPlanGenerator`):

| Ключ | Значение по умолчанию | За что отвечает |
|---|---|---|
| `daily_tasks_count` | 3 | Сколько заданий назначать школьнику в день |
| `task_repeat_cooldown_days` | 7 | Не повторять один шаблон задания раньше, чем через столько дней |
| `suggestion_min_delta_pp` | 10 | Минимальный отрыв конкурента от текущей цели (в п.п.), чтобы вообще предложить смену |
| `suggestion_min_streak` | 2 | Сколько попыток подряд отрыв должен держаться, прежде чем показать предложение |
| `snapshot_top_n` | 3 | Сколько профессий (топ по %) сохранять в историю снапшотов на каждую попытку |

Это гипотезы для старта, не результат исследования — их стоит
пересмотреть, когда наберётся статистика реального использования (например,
если школьники жалуются, что заданий мало/много, или что предложения
сменить профессию приходят слишком часто/редко).

генерация при заходе школьника остаётся резервным вариантом.

## 7. Варианты развития системы

Что уже заложено в архитектуре, но не реализовано — примерно в порядке
убывания практической ценности:

### 7.1 Роль «Родитель»
Отдельный аккаунт/привязка родитель↔ребёнок, read-only дашборд с тем же
профилем навыков, целью и прогрессом, что видит сам школьник — плюс
уведомления о крупных изменениях (новая рекомендация профессии, N дней без
выполненных заданий). Требует новую сущность связи родитель–школьник и
отдельную ветку меню/страниц; расчётная логика (уровни, %, подбор) уже
готова и переиспользуется без изменений.

### 7.2 Слой «характеристик» между вопросом и навыком
Сейчас вопрос напрямую даёт баллы в один навык (тест 1:1 с навыком, как
описано в исходной спецификации п.2.2 «навыки агрегируются из
характеристик»). Более гибкая модель — промежуточная сущность
«характеристика» (аналитическое мышление, коммуникация и т.д.), а навык —
агрегат из нескольких характеристик с весами. Позволит одному вопросу
влиять на несколько навыков сразу и делать более точные психологические
тесты (не привязанные жёстко к одному навыку).

### 7.3 Психологические тесты как отдельный тип
Спецификация упоминает два типа тестов — «на навыки» (есть) и
«психологические, определяющие склонности» (нет). Технически это
расширение поля `level_band`-подобного различения на уровне `SkillTest` —
добавить `type` (`skill` / `psychological`), и для психологических тестов
считать не % против шкалы 0–100, а профиль склонностей, который тоже
участвует в подборе профессии наравне с навыками.

### 7.4 Мягкий прогресс от выполнения заданий
Сейчас выполнение задания не двигает уровень напрямую (осознанное решение
— см. раздел 3.3). Альтернатива на будущее — небольшой, явно помеченный
как «предварительный» прирост уровня за выполненные задания, который
сгорает/подтверждается при следующей пересдаче теста. Это отдельное
продуктовое решение, требует новой модели «мягкого» прогресса, чтобы не
путать его с «настоящим» результатом теста.

### 7.5 Геймификация
Стрики (дни подряд с выполненными заданиями), бейджи за пройденные тесты
или закрытые профессии, прогресс-бар до следующего уровня навыка. Не
требует новых доменных сущностей — считается поверх уже существующей
истории (`skills_development_assignments.completed_at`,
`skills_test_attempts`), можно сделать чисто на фронтенде + одним
вычисляемым GraphQL-полем.

### 7.6 Уведомления
Push/email/сообщение в мессенджер-боте (в монорепо уже есть инфраструктура
Max/Telegram-ботов) о новом предложении сменить профессию, о пропущенных
днях без заданий, о приближении к следующему уровню навыка. Требует
проверки, какой канал уведомлений уже есть в основном приложении, и
подписки на события `ProfessionSuggestionEngine`/`DevelopmentPlanGenerator`.

### 7.7 Адаптивное тестирование
Сейчас все вопросы теста фиксированы и показываются в одном порядке всем.
Можно сделать динамический подбор вопросов по сложности в реальном времени
(следующий вопрос легче/сложнее в зависимости от предыдущего ответа) —
короче тест, точнее оценка. Требует пересмотра `SkillsTestResolver`/
`SkillsAttemptResolver` и добавления сложности на уровне вопроса, а не
только варианта ответа.

### 7.8 Экспорт отчётов и аналитика для школы/администрации
CSV/PDF-выгрузка профиля класса или школы (агрегированные уровни навыков,
топ выбранных профессий) — полезно для профориентационной работы школы
целиком, не только для отдельного ученика. Строится поверх существующих
`skillsAdminStats`/`skillsAdminRecentAttempts` плюс новый агрегирующий
резолвер по `StudentProfile.school`.

### 7.9 Реальные данные о профессиях
Сейчас описания и требования профессий — экспертная оценка администратора
вручную. В перспективе — интеграция с внешними справочниками профессий
(зарплатные вилки, востребованность, учебные заведения) через API или
периодический импорт, чтобы рекомендации опирались не только на
соответствие навыков, но и на актуальность профессии на рынке труда.
