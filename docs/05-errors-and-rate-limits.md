# Ошибки и лимиты

Все ответы API — JSON, включая ошибки. Формат тела ошибки отличается в
зависимости от её типа (историческая особенность, не единый конверт) —
ориентируйтесь на HTTP-код, а поле `message` всегда содержит
человекочитаемое описание на русском.

## Коды ответов

| HTTP | Когда | Пример тела |
|---|---|---|
| `200` / `201` | успех | — |
| `401` | не передан / неверен / отозван API-ключ | `{"error":"unauthenticated","message":"..."}` |
| `403` | аккаунт временно отключён | `{"error":"tenant_suspended","message":"..."}` |
| `404` | ресурс не найден (или принадлежит другому аккаунту) | `{"ok":false,"message":"..."}` |
| `422` | ошибка валидации тела запроса | см. ниже |
| `429` | превышен лимит запросов | `{"ok":false,"message":"..."}` |
| `502` | сервис ответов на вопросы временно недоступен | `{"error":"service_unavailable","message":"..."}` |

### Ошибки валидации (`422`)

```json
{
  "ok": false,
  "message": "The section field is required. (and 1 more error)",
  "errors": [
    { "name": "section", "message": "The section field is required." },
    { "name": "file", "message": "The file field is required." }
  ]
}
```

`errors` — список всех невалидных полей сразу, не только первого.

## Rate limiting

Один общий лимит на **весь аккаунт** — **60 запросов в минуту**,
действует сразу на все API-ключи аккаунта и на все эндпоинты (документы
+ чат) вместе, не по отдельности.

Каждый ответ содержит заголовки:

| Заголовок | Описание |
|---|---|
| `X-RateLimit-Limit` | лимит за окно (`60`) |
| `X-RateLimit-Remaining` | сколько запросов осталось в текущем окне |
| `Retry-After` | (только при `429`) через сколько секунд можно повторить |

При превышении:

```
HTTP/1.1 429 Too Many Requests
Retry-After: 37
X-RateLimit-Limit: 60
X-RateLimit-Remaining: 0
```

```json
{ "ok": false, "message": "Слишком много запросов, попробуйте позже." }
```

**Рекомендация:** ориентируйтесь на `X-RateLimit-Remaining`, а при `429`
делайте retry с задержкой не меньше `Retry-After`, а не сразу.

## Транзиентные ошибки (`502`)

`POST /api/v1/chat/ask` иногда может ответить `502`, если сервис ответов
на вопросы временно недоступен (перезапуск, пиковая нагрузка). Это не
ошибка вашего запроса — сделайте retry с небольшой задержкой (1–2
попытки обычно достаточно).
