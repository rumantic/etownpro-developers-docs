# SEO-шаблоны объявлений и страниц — руководство

Практическое руководство по конструктору SEO-схем (`/admin/seo-templates`):
как из полей объявления и гео-справочника собираются заголовок H1, текст
вкладки браузера (`<title>`), `meta description` и `og:title`/`og:description`
— и как настроить это под себя, если платформенный вариант по умолчанию не
устраивает. Техническая архитектура (движок шаблонов, GraphQL-схема, каскад
резолверов) описана в другом месте — здесь только «как этим пользоваться».

## 1. Общая идея одним абзацем

Раньше заголовок H1, `<title>` и `meta description` объявления или страницы
города/региона либо вводились вручную на каждую запись, либо были жёстко
зашитой фразой — одинаковой для всех тенантов, без возможности что-то
поменять. Конструктор SEO-схем позволяет описать **формулу** («шаблон») —
как собрать эти тексты из полей записи (цена, комнаты, город, тип сделки и
т.п.), с условиями («эта формула — только для коммерции в аренду») и
запасными вариантами на случай пустых полей. Ничего не настраивая, сайт
использует встроенный **платформенный дефолт** — тот же текст, что
показывался до появления этой функции.

```
Тенант ничего не делает → работает платформенный дефолт
Тенант создаёт схему → редактирует формулы → включает схему → она вступает в силу
```

## 2. Где искать в админке

Личный кабинет администратора → **SEO-шаблоны** (пункт меню рядом с «Форма
поиска»), либо напрямую `/admin/seo-templates`.

Наверху — вкладки разделов, у каждого свой набор схем и токенов:

| Вкладка | На что влияет |
|---|---|
| **Объявления** | Карточка одного объявления: `<title>`, meta description, og-теги. (H1 самой карточки — см. [ограничения](#11-ограничения-текущей-версии)) |
| **Списки объявлений** | Страница вида «Квартиры на продажу в Самаре» — H1, `<title>`, meta description |
| **Регионы** | Страница региона (список городов региона) |
| **Города** | Страница города (список объявлений в городе) |
| **Районы** | Зарезервировано на будущее — отдельной публичной страницы района на сайте пока нет |

## 3. Что уже работает без единой настройки

У каждого раздела есть **платформенный дефолт** — формула, зашитая в
платформу, которая воспроизводит тот текст, что показывался на сайте и
раньше. Если тенант не создал ни одной своей схемы (или создал, но не
включил) — работает именно она. Список схем в админке в этом случае просто
пустой, это нормальное состояние, а не ошибка.

## 4. Как создать свою схему — по шагам

1. Откройте нужную вкладку раздела (например, «Города»).
2. Нажмите **«Создать шаблоны»**.
3. Появится новая схема — **черновик**, уже заполненный текстом
   платформенного дефолта на все языки сайта. Ничего придумывать с нуля не
   нужно — редактор сразу открывается на этом черновике.
4. Поправьте нужные поля (H1, заголовок вкладки, meta description,
   og-теги) — см. [мини-язык шаблонов](#6-мини-язык-шаблонов) и
   [токены](#7-токены-по-разделам) ниже. Правьте только то, что хотите
   изменить — остальные поля можно оставить как есть.
5. При необходимости задайте [условия применения](#5-условия-применения-и-приоритет--памятка)
   — например, только для типа «Коммерческая» и сделки «Аренда».
6. Нажмите **«Обновить предпросмотр»**, чтобы увидеть результат на
   примере записи, прежде чем сохранять.
7. Отметьте чекбокс **«Схема включена»** и нажмите **«Сохранить»**.

Пока чекбокс не отмечен — схема сохраняется, но не влияет на сайт (в
списке схем такая помечена бейджем «Черновик»). Включить/выключить
схему можно и позже, не заходя в редактор — чекбоксом прямо в списке.

## 5. Условия применения и приоритет — памятка

Это самая частая причина путаницы, если схем несколько — прочитайте перед
тем, как заводить вторую схему в одном разделе.

- **Условия** (`Тип объекта` / `Тип сделки`) сужают круг записей, к которым
  применяется схема. Ничего не выбрано в обоих полях — схема подходит
  **всем** записям раздела (это и есть «схема по умолчанию» тенанта).
- Если схем в разделе несколько, они проверяются **от большего приоритета
  к меньшему**, и применяется **первая**, чьи условия подошли записи.
  Проверка на этом останавливается — остальные схемы, даже подходящие,
  уже не учитываются.
- **Отсюда правило:** более узкие по условиям схемы должны иметь **более
  высокий** приоритет, чем схема-катчол (без условий). Если сделать
  наоборот — общая схема с высоким приоритетом «перехватит» все записи
  раньше, чем до узкой схемы вообще дойдёт очередь, и узкая схема никогда
  не сработает.

  ```
  Правильно:
    Приоритет 10 — «Коммерция в аренду» (условия: тип=Коммерческая, сделка=Аренда)
    Приоритет 0  — «Все объявления» (без условий)

  Неправильно (узкая схема не сработает никогда):
    Приоритет 10 — «Все объявления» (без условий)
    Приоритет 0  — «Коммерция в аренду» (условия: тип=Коммерческая, сделка=Аренда)
  ```

- Если **ни одна** схема тенанта не подошла (или схем вообще нет) —
  в силу вступает платформенный дефолт (см. §3), а не пустой текст.
- Условия внутри одного поля работают через «ИЛИ» (выбрали «Квартиры» и
  «Дома» — схема подходит обоим типам), а между полями — через «И»
  (выбрали ещё и «Аренда» — теперь схема подходит только квартирам/домам
  именно в аренду, но не в продажу).

## 6. Мини-язык шаблонов

Поля H1/title/meta description/og-теги — это не голый текст, а шаблон:
можно подставлять значения полей записи и добавлять условные куски текста.
Специально сделан **узким и безопасным** — это не язык программирования, в
нём нельзя вызвать произвольный код, только то, что описано ниже.

**Подстановка токена:**

```
{{ city.name }}
```
Выведет название города. Если поле пустое — просто ничего не выведется
(если не указан запасной вариант, см. ниже).

**Фильтр — изменяет значение перед выводом:**

```
{{ price|number }}          → 6 500 000
{{ price|currency }}        → 6 500 000 ₽
```

Фильтров можно применить несколько подряд, через `|`:

```
{{ description|strip_tags|truncate:200 }}
```

**Запасной вариант, если поле пустое** — оператор `??`:

```
{{ district.name ?? "без района" }}
```

**Условный кусок текста** — выводится, только если поле непустое:

```
{% if district %}, {{ district.name }}{% endif %}
```

Можно с «иначе»:

```
{% if rooms %}{{ rooms }}-комн.{% else %}Студия{% endif %}
```

И со сравнением с конкретным значением:

```
{% if type == "apartment" %}Квартира{% endif %}
```

Условные блоки можно вкладывать друг в друга — например, чтобы не выводить
запятую перед районом, если города тоже нет:

```
{{ city.name }}{% if district %}, {{ district.name }}{% if street %}, {{ street.name }}{% endif %}{% endif %}
```

Если в шаблоне опечатка (не закрыт `{% if %}`, неизвестный фильтр) —
редактор откажется сохранить схему и покажет, в чём именно ошибка.

## 7. Токены по разделам

### Объявления

| Токен | Значение |
|---|---|
| `title` | Заголовок объявления, введённый автором |
| `description` | Описание объявления (содержит HTML — используйте фильтр `strip_tags` в meta description) |
| `type_label` | Тип объекта («Квартиры», «Дома», …) |
| `deal_label` | Тип сделки («Продажа», «Аренда», «Посуточно») |
| `rooms` | Количество комнат |
| `price` | Цена (число) |
| `area_total` | Общая площадь |
| `floor` / `floors_total` | Этаж / этажность дома |
| `metro_name` | Ближайшее метро |
| `country.name` / `region.name` / `city.name` / `district.name` / `street.name` | Гео-цепочка объявления |
| `custom_fields.<ключ>` | Любое ваше пользовательское поле объявления (см. «Редактор форм» в админке) — подставляется автоматически, отдельно заводить не нужно |

### Списки объявлений

| Токен | Значение |
|---|---|
| `type_label` / `deal_label` | Тип объекта / тип сделки текущей подборки |
| `city.name` | Город подборки |
| `count` | Количество объявлений в подборке |

### Регионы

| Токен | Значение |
|---|---|
| `name` | Название региона |
| `cities_count` | Количество городов в регионе |
| `properties_count` | Количество объявлений в регионе |

### Города

| Токен | Значение |
|---|---|
| `name` | Название города |
| `region.name` | Название региона |
| `properties_count` | Количество объявлений в городе |

### Районы

| Токен | Значение |
|---|---|
| `name` | Название района |
| `city.name` | Название города |
| `properties_count` | Количество объявлений в районе |

Полный список токенов с подсказками есть прямо в редакторе схемы (правая
колонка «Доступные токены») — клик по токену вставляет его в последнее
выбранное поле.

## 8. Фильтры

| Фильтр | Что делает | Пример |
|---|---|---|
| `number` | Число с разделителем разрядов | `{{ price\|number }}` → `6 500 000` |
| `currency` | Число + символ валюты объявления | `{{ price\|currency }}` → `6 500 000 ₽` |
| `plural` | Форма слова по числу (3 варианта — славянское правило 1/2-4/5-0, 2 варианта — «одно/остальные», как в английском) | `{{ count }} {{ count\|plural:"объявление","объявления","объявлений" }}` |
| `upper` / `lower` | ВЕРХНИЙ / нижний регистр | `{{ deal_label\|lower }}` → `аренда` |
| `capitalize` | Первая буква заглавная, остальное как есть | `{{ deal_label\|capitalize }}` |
| `strip_tags` | Убрать HTML-теги — обязателен для `description` в meta-полях | `{{ description\|strip_tags }}` |
| `truncate:N` | Обрезать текст до N символов, добавить «…» | `{{ description\|strip_tags\|truncate:200 }}` |
| `translit` | Транслитерация — пригодится, если в будущем появится шаблонизация URL | `{{ city.name\|translit }}` |

## 9. Предпросмотр

Кнопка **«Обновить предпросмотр»** в редакторе схемы рендерит текущие (ещё
не сохранённые) формулы на **правдоподобном примере записи** — не на
реальном объявлении/городе тенанта, а на условном образце («2-комнатная
квартира, Москва, Хамовники» и т.п.). Это значит, что реальный текст на
сайте будет отличаться в деталях (другой город, другая цена), но точно
покажет, правильно ли сработали условные блоки, фильтры и запасные
варианты — синтаксические и логические ошибки шаблона видно сразу, не
дожидаясь публикации.

## 10. Что главнее: ручное поле объекта, схема или дефолт

Порядок применения (сверху вниз, первое найденное значение побеждает):

1. **Ручное поле самой записи**, если оно есть и заполнено — например,
   `meta_title`/`meta_description`, которые можно задать прямо на
   странице региона/города/района в справочниках (перенесено из легаси).
   Для объявлений таким «ручным полем» выступает сам заголовок/описание,
   введённые автором — они участвуют в схеме как токены `title`/
   `description`, а не как отдельный уровень поверх неё.
2. **Ваша схема**, если она включена и её условия подошли записи (см. §5).
   Если в схеме заполнено не всё — H1 берётся из платформенного дефолта,
   `title` берётся из H1, `og:title` из `title`, `og:description` из
   `meta description` (см. подсказки прямо под полями в редакторе).
3. **Платформенный дефолт** — если ни своей схемы, ни ручного поля нет.

## 11. Ограничения текущей версии

Сознательно не реализовано в этой версии:

- **H1 самой карточки объявления** (не списка, а именно страницы одного
  объекта) на сайте по-прежнему берётся напрямую из заголовка, введённого
  автором — своя H1-формула из схемы пока влияет только на `<title>`
  вкладки и meta-теги этой страницы, не на видимый заголовок на самой
  странице.
- **Шаблонизация URL объявления** — адрес страницы объявления собирается
  фиксированным алгоритмом (тип + город + улица), настроить его состав
  через схему пока нельзя.
- **Условия по гео** — в редакторе можно задать условие по типу объекта и
  типу сделки; условие «только для такого-то города/региона» технически
  поддержано на бэкенде, но в интерфейсе редактора пока не выведено.
- **Условия для разделов «Регионы»/«Города»/«Районы»** — схемы этих
  разделов всегда действуют на все записи раздела (без условий).

## 12. Частые вопросы

**Я создал схему, но на сайте ничего не изменилось.**
Проверьте чекбокс «Схема включена» (или переключатель в списке схем) —
только что созданная схема выключена по умолчанию, чтобы не публиковать
неготовый текст. Также проверьте, что условия схемы (если заданы) вообще
подходят той записи, которую вы смотрите.

**Можно ли сделать несколько разных схем для разных типов объявлений?**
Да — заведите отдельную схему на каждый тип/сделку с соответствующими
условиями и разным приоритетом (см. §5). Схема без условий («для всех») —
это, по сути, замена платформенного дефолта, держите её самым низким
приоритетом.

**Что будет, если я введу в шаблон текст с ошибкой (незакрытый `{% if %}`)?**
Редактор не даст сохранить схему и покажет сообщение с описанием ошибки —
битый шаблон никогда не попадёт на публичный сайт.

**Нужно ли что-то менять в объявлениях, если я включил свою схему?**
Нет — схема применяется автоматически ко всем существующим и новым
записям, подходящим под её условия, без правки самих объявлений.
