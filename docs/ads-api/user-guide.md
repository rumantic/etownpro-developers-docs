# Импорт объявлений с ads-api.ru — руководство пользователя

Практическое руководство для агентства/риэлтора, который настраивает
автоматическую загрузку объявлений с Avito, ЦИАН, Яндекс.Недвижимости и
других площадок через сервис-агрегатор **ads-api.ru**. Здесь — как это
работает изнутри, какие поля за что отвечают и какие грабли встречаются
на практике (с реальными примерами). Техническая архитектура (очереди,
дедупликация, модели данных) здесь не описывается — только то, что нужно
знать, чтобы настройка не удивляла.

## 1. Общая идея одним абзацем

Ads-api.ru — независимый сервис, который сам круглосуточно собирает
объявления с досок объявлений (Avito, ЦИАН, Яндекс.Недвижимость, Юла,
Sob.ru и др.) и отдаёт их по подписке через свой API. Наша платформа раз
в час стучится к нему по вашим настройкам (**задачам**) и превращает
найденные объявления в обычные объекты на вашем сайте — с теми же полями,
что и у объявления, заведённого руками. Чем точнее настроена задача, тем
точнее выборка: слишком широкий фильтр тащит мусор из других городов,
слишком узкий — не находит ничего вообще.

```
Ваша задача (фильтр) → запрос к ads-api.ru раз в час →
→ найденные объявления → фильтр «оставить только эти города» (опционально) →
→ новые объекты на сайте (или обновление уже загруженных)
```

Важно сразу понять главное ограничение: **фильтр города — это не наш
справочник городов**, а обычный текстовый поиск по базе ads-api.ru,
которая понятия не имеет о нашей платформе. Он ищет введённое слово как
подстроку в адресе объявления — со всеми вытекающими последствиями,
разобранными в §5.

## 2. Источник и Задача — в чём разница

- **Источник** — это ваша учётная запись ads-api.ru (email + токен) плюс
  общие настройки: как показывать контакт в карточке объявления, удалять
  ли старые объявления, обновлять ли уже загруженные. Один источник на
  агентство — в норме он один, добавляется администратором один раз.
- **Задача** — это конкретный фильтр внутри источника: «Квартиры, Москва,
  сдам» или «Дома, Красногорск, продажа». Задач под одним источником
  может быть сколько угодно — обычно по одной на город/район/сегмент,
  который вы обслуживаете.

Практическое следствие: **все задачи одного источника расходуют общий
лимит запросов ads-api.ru** и относятся к одному и тому же массиву
объявлений — если два фильтра пересекаются, они видят один и тот же
объект, а не два разных (подробнее в §8).

## 3. Настройка источника

Обычно это делает администратор сайта один раз при подключении парсера —
рядовому агенту сюда заходить не нужно, но полезно понимать, что там
настроено:

| Поле | Что значит |
|---|---|
| Email / Токен | Учётные данные вашего личного кабинета на ads-api.ru |
| Контакт в карточке объявления | Что видит посетитель сайта: ссылку на исходное объявление, единый телефон агентства, либо карточку реального автора-риэлтора платформы (см. §8) |
| Обновлять уже загруженные объявления | Если выключено — повторно найденное объявление не перезаписывает уже сохранённые данные (полезно, если вы вручную поправили описание и не хотите, чтобы его затёрло при следующем прогоне) |
| Автоочистка старых объявлений | Через сколько дней без обновления с площадки объявление считается снятым и удаляется у вас |
| Загружать без телефона по умолчанию | Для Avito/Юлы часто нужно включать явно — иначе часть объявлений этих площадок не попадёт в выборку вовсе |

## 4. Настройка задачи: поля формы

Каждая задача — это отдельная карточка на странице источника
(**Задачи → Добавить задачу**):

| Поле | Что значит |
|---|---|
| Название | Только для вас — как задача называется в списке |
| Владелец объявлений | Чьи это будут объявления в личном кабинете — см. §8 |
| Категории | Квартиры / Дома, дачи, коттеджи / Комнаты / Земельные участки / Гаражи / Коммерческая — пусто = любая |
| Тип сделки | Продам / Сдам — пусто = любой |
| Город / регион | Текстовый фильтр к ads-api.ru — см. §5, самое важное поле формы |
| Метро | Фильтр по станциям — см. §7 |
| Ограничить сохранение городами | Наш собственный фильтр поверх ответа ads-api.ru — см. §6 |
| Площадки-источники | Avito, ЦИАН, Яндекс.Недвижимость и т.д. — пусто = все |
| Тип продавца | Частное лицо / Агентство / Собственник |
| Цена от / до | Простой диапазон цены |
| Объявления без телефона | «Как задано у источника» / «Включать» / «Только с телефоном» |
| Свежих объявлений за один запуск | Сколько объявлений забирать за один прогон (по умолчанию 100) — это не общий лимит, а размер «порции» на один час, уже загруженные не расходуют лимит повторно |
| Публиковать новые сразу | Если выключить — новые объекты этой задачи попадут в «Объявления» неопубликованным черновиком, нужно будет опубликовать руками |
| Вне общего цикла | Задача не запускается по расписанию сама, только вручную кнопкой «Запустить» |
| Постепенная догрузка истории (backfill) | Разовая выгрузка большого архива объявлений за прошлые даты вместо обычного «топ-N свежих» — отдельный редкий сценарий, не для повседневной настройки |

## 5. Город / регион — самое важное и самое коварное поле

Это поле буквально пересылается в ads-api.ru как их GET-параметр `city` —
никакой обработки с нашей стороны нет. У этого параметра три особенности,
которые стоит знать заранее, а не выяснять на живых объявлениях.

### 5.1. Это поиск подстроки, а не точное совпадение

ads-api.ru ищет введённое слово **где угодно в адресе объявления** —
в названии города, района, региона. Это удобно (можно перечислить
несколько городов через `|`: `Москва|Тула`), но означает, что слишком
короткое или слишком общее слово ловит вообще не то, что вы имели в
виду.

**Реальный пример.** Задача с фильтром `Красногорский` (в расчёте на
Красногорский городской округ Московской области) вместо этого поймала
объявление из посёлка **Красногорский в Челябинской области** — потому
что слово «Красногорский» тоже встретилось в его адресе. Регион,
который вы не обслуживаете, тихо оказался в вашей выгрузке.

### 5.2. Название округа/района у ads-api.ru не всегда совпадает с официальным

Официальное название на картах и в документах — не то же самое, что
хранится в базе ads-api.ru. Расхождение может быть буквально в одном
окончании слова.

**Реальный пример.** Задача с фильтром «**Красногорск**ий городской
округ» (прилагательное, как пишут на картах) не находила вообще ничего —
`0` объявлений на каждом прогоне, месяцами. У ads-api.ru тот же округ
записан как «**Красногорск** городской округ» (без окончания «-ий») —
и с этим написанием фильтр сразу нашёл сотни объявлений.

**Как проверять.** Если после сохранения задачи столбец «Объявления»
в списке задач стабильно показывает `0 из 0` при том, что задача активна
и площадки в этом городе точно есть — почти наверняка дело в формулировке
фильтра, а не в том, что «просто пока нет объявлений». Попробуйте
несколько вариантов написания (с окончанием и без, слитно/раздельно,
«округ Х» и «Х округ») и посмотрите на результат первого прогона.

### 5.3. Одно и то же название бывает в разных регионах

Небольшие населённые пункты часто называются одинаково в совершенно
разных областях. Ads-api.ru не знает, какой из них ваш — он находит все
совпадения по всей базе.

**Реальный пример.** Название «Отрадное» одновременно существует и как
посёлок в Красногорском округе (Московская область), и как отдельный
город в **Ленинградской области**. Задача с фильтром «Отрадное» получила
объекты из обоих регионов — до тех пор, пока их не заметили и не
разобрали руками.

**Как проверять.** Загляните на вкладку **«Аналитика загрузок»** источника,
раздел «По городам за период» — если рядом с ожидаемым городом появился
незнакомый регион, это оно. Единственный надёжный способ починить —
убрать неоднозначное слово из фильтра либо, если без него никак,
регулярно проверять результат и вручную переносить/удалять залётные
объекты.

### 5.4. Практический вывод

Для «одно объявление = один явный город» задача (типа «Москва», «Тула»)
эти риски минимальны — короткое, однозначное, широко известное название
редко с чем-то пересекается. Проблема возникает именно с **округами,
районами и малыми населёнными пунктами** — там стоит:

1. После сохранения сразу запустить задачу кнопкой ▶ и посмотреть
   результат, а не ждать первого прогона по расписанию.
2. Если результат `0` — попробовать другую формулировку названия.
3. Если результат подозрительно большой или разнородный — заглянуть в
   «Аналитику загрузок» по городам и проверить, не затесался ли чужой
   регион.

## 6. «Ограничить сохранение городами» — второй фильтр, уже свой

Поле `Город / регион` (§5) — это то, что мы **просим** у ads-api.ru.
«Ограничить сохранение городами» — это то, что мы **оставляем себе** из
полученного ответа, уже на нашей стороне, точным сравнением (без поиска
подстрок). Разница практическая:

- `Город / регион = Красногорск` без ограничения — сохранится всё, что
  ads-api.ru нашёл по этому слову (а он ищет подстрокой, см. §5.1).
- `Город / регион = Красногорск` **+** `Ограничить сохранение городами =
  Красногорск` — из найденного останутся только объекты, у которых
  распознанный город **точно** равен «Красногорск», остальное будет
  тихо пропущено (это видно как «Пропущено» в истории прогонов).

**Когда это обязательно нужно.** Если у вас несколько задач одного
источника обслуживают разные части одного и того же города/округа с
**разными владельцами объявлений** (см. §8) — например, одна задача
только на сам город, другая на пригороды — обязательно пропишите
«Ограничить сохранение городами» так, чтобы задачи не пересекались между
собой. Иначе один и тот же объект может считаться подходящим под фильтр
сразу двух задач, и тогда владельцем окажется тот риэлтор, чья задача
последней его обновила — то есть, по сути, случайно.

Формат поля — простой список через запятую: `Москва, Красногорск`.
Пусто — сохранять всё, что нашлось по фильтру выше, без дополнительного
отсева.

## 7. Метро

Отдельный фильтр по станциям — работает только для городов, где у
ads-api.ru есть метро (Москва, Санкт-Петербург и ещё несколько). Можно
выбрать станции из справочника или вписать своё значение (например, для
МЦК/МЦД или если станции нет в списке).

Две вещи, которые стоит знать:

- **Для города с метро указывайте именно станцию, а не район** — иначе
  ads-api.ru не поймёт запрос и не найдёт ничего. Районы как фильтр
  работают только у городов **без** метро.
- Если выбрано несколько станций сразу, платформа под капотом делает
  по ним отдельные запросы один за другим (сам ads-api.ru не умеет
  принимать несколько станций в одном запросе) — вы этого не видите в
  интерфейсе, но именно поэтому прогон с большим числом станций занимает
  заметно больше времени, чем обычный.

## 8. Владелец объявлений и раскидка по риэлторам

Поле **«Владелец объявлений»** определяет, кто в личном кабинете видит
загруженные этой задачей объекты вместе с контактами и ссылкой на
источник — то же самое, как если бы риэлтор завёл их вручную. Пусто —
объекты не привязаны ни к кому в ЛК (но по-прежнему видны в админке).

**Частый сценарий**: развести объявления по разным риэлторам через
несколько задач одного источника — «Квартиры, город N» на одного,
«Дома, пригороды N» на другого. Здесь важно понимать один нюанс
архитектуры платформы:

> Объявления одного источника считаются **дубликатом по номеру
> объявления на площадке**, а не по задаче. Если объект подходит сразу
> под фильтры двух ваших задач — это **одна и та же карточка** на сайте,
> а не две. При каждом прогоне она обновляется той задачей, которая её
> в этот раз нашла, — включая владельца.

Практически это означает: если задачи двух риэлторов пересекаются по
городу (см. пример с Красногорском в §5.2 — пока задача на округ не
находила вообще ничего, все пограничные объекты автоматически доставались
задаче с более широким фильтром), объект может «переходить» от одного
риэлтора к другому от прогона к прогону — не потому что кто-то что-то
делает специально, а потому что фильтры пересекаются.

**Как избежать.** Каждой задаче с отдельным владельцем — свой явный,
непересекающийся список в «Ограничить сохранение городами» (§6). Если
сомневаетесь, пересекаются ли фильтры — посмотрите на реальные
результаты обеих задач в «Аналитике загрузок» за пару дней.

## 9. Расписание, лимит за прогон и публикация

- Активные задачи запускаются автоматически, по кругу (ориентировочно
  раз в час — точный интервал определяется общей нагрузкой платформы).
- «Свежих объявлений за один запуск» — это размер порции одного прогона,
  а не общий предел: уже загруженные объекты в следующий раз просто не
  расходуют этот лимит повторно, туда попадают только новые/обновившиеся.
- «Публиковать новые сразу» стоит выключить, если вы хотите сначала
  проверять глазами каждое новое объявление перед публикацией — тогда
  оно появится в разделе «Объявления» неопубликованным, и вы решаете
  сами, когда включить показ на сайте. На уже загруженные объекты и на
  ваше решение опубликовать/снять с публикации конкретный объект это не
  влияет — только на новые.
- «Вне общего цикла» — полезно на время отладки фильтра: задача не будет
  запускаться сама по расписанию, только когда вы явно нажмёте
  ▶ «Запустить».

## 10. Как проверить, что задача реально работает

Не полагайтесь на ощущение «наверное работает» — платформа показывает
реальные цифры в двух местах:

1. **Список задач**, столбец «Объявления» — формат «X из Y»: сколько
   объектов из найденных на последнем прогоне реально сохранено (Y может
   быть больше X из-за фильтра «Ограничить сохранение городами» или
   дублей). Если тут стабильно `0 из 0` — фильтр в поле «Город / регион»
   ничего не находит, см. §5.
2. **Вкладка «Аналитика загрузок»** источника — сводка за 7/30/90 дней:
   сколько запусков, сколько объявлений получено/создано/обновлено,
   сколько ошибок, и отдельная разбивка **по городам** — самое полезное
   место, чтобы заметить, что в выборку затесался чужой регион (см.
   пример с «Отрадное» в §5.3).

## 11. Чек-лист перед тем как оставить задачу в покое

- [ ] После сохранения — сразу запустили задачу кнопкой ▶, а не ждали
      расписания.
- [ ] Результат первого прогона не `0 из 0` (если ожидали найти
      объявления).
- [ ] В «Аналитике загрузок» по городам нет незнакомых регионов.
- [ ] Если у нескольких задач одного источника разные владельцы —
      в каждой заполнено непересекающееся «Ограничить сохранение
      городами».
- [ ] Для города с метро в поле «Метро» выбрана станция, а не район.

## 12. Частые вопросы

**Задача активна, но «Объявления» всегда 0 из 0 — что не так?**
Почти всегда — формулировка фильтра «Город / регион» не совпадает с тем,
как это название хранится в базе ads-api.ru (см. §5.2). Попробуйте
несколько вариантов написания и проверяйте результат сразу после
сохранения, не дожидаясь расписания.

**Почему объект оказался у другого риэлтора, а не у того, кого я
назначил?**
Скорее всего фильтры двух задач одного источника пересекаются, и объект
подходит под обе — тогда владельцем становится задача, которая
обновила его последней. Разведите задачи через «Ограничить сохранение
городами» (§6, §8).

**В выгрузке появился объект из совсем другого региона — как так?**
Слово в фильтре «Город / регион» либо слишком общее (совпало с чужим
названием как подстрока, §5.1), либо название неоднозначно и
существует в нескольких регионах одновременно (§5.3). Проверьте
«Аналитику загрузок» по городам и, если нужно, уберите проблемное слово
из фильтра.

**Можно ли исключить конкретный город из широкого фильтра (например,
«весь округ, но без областного центра»)?**
Через поле «Город / регион» — нет, оно не поддерживает исключения.
Обычный обходной путь — перечислить через `|` конкретные населённые
пункты, которые нужны, вместо одного общего названия округа/района.

**Что будет, если выключить задачу?** Уже загруженные объекты никуда не
денутся — выключение просто останавливает дальнейшие прогоны по
расписанию (и по кнопке ▶, пока она не активна).

**Где взять email и токен для источника?** В личном кабинете на
ads-api.ru, на странице подключения к API — эти данные обычно вводит
администратор сайта один раз при подключении.
