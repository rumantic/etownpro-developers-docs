# Аутентификация

## Заголовок

Каждый запрос к API должен содержать заголовок:

```
Authorization: Bearer <ваш API-ключ>
```

## Как устроен ключ

- Ключ выпускается администратором аккаунта в личном кабинете
  (**База знаний → API-ключи**)
- Ключ привязан к аккаунту (сайту) целиком, а не к конкретному
  сотруднику — можно выпустить сколько угодно ключей с разными
  названиями (например, для разных интеграций), у всех одинаковый
  полный доступ
- Ключ не имеет срока действия — работает, пока его не отозвали вручную
- Полный секрет виден только один раз, в момент создания. Личный кабинет
  хранит и показывает только название ключа, дату создания и дату
  последнего использования — сам секрет восстановить нельзя

## Если ключ скомпрометирован

Специального эндпоинта «перевыпустить ключ» нет — отзовите
скомпрометированный ключ в личном кабинете и создайте новый. Отзыв
действует немедленно: все последующие запросы с этим ключом получат `401`.

## Рекомендации по хранению

- Не встраивайте ключ в клиентский (браузерный/мобильный) код — он
  предназначен для серверных интеграций
- Храните в переменных окружения / секрет-менеджере, не в git
- Если используете несколько интеграций — заведите под каждую отдельный
  ключ, чтобы можно было отозвать одну интеграцию, не трогая остальные

## Ошибки авторизации

| HTTP | `error`             | Когда |
|---|---|---|
| `401` | `unauthenticated` | заголовок `Authorization` не передан |
| `401` | `unauthenticated` | ключ неверен или уже отозван |
| `403` | `forbidden`       | ключ валиден, но действие вне его прав *(зарезервировано на будущее — см. ниже)* |
| `403` | `tenant_suspended`| аккаунт временно отключён |

```json
{ "error": "unauthenticated", "message": "Неверный или отозванный API-ключ." }
```

> Все ключи, выпущенные через личный кабинет, сейчас получают полный
> доступ (документы + чат) — код для точечных прав по типу действия уже
> заложен на стороне сервера, но выбор ограниченных прав в интерфейсе
> создания ключа пока не предусмотрен. Если вашей интеграции важно иметь
> отдельный ключ только на чтение — напишите нам.

## Rate limiting

Один общий лимит на **весь аккаунт**, действует сразу на все ключи и все
эндпоинты. Подробности — в разделе [«Ошибки и лимиты»](05-errors-and-rate-limits.md).
